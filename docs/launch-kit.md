# Ignis launch kit

## Positioning

**Ignis: a Rust 3D engine humans and AI agents can build in together.**

The differentiator is the inspectable build/run/capture/refine loop through
the same typed command API used by the native editor. Lead with a concrete
interaction, then show the result. Rust, MCP, offline operation and procedural
authoring explain why it is interesting; unsupported scale claims do not.

Canonical repository: https://github.com/zerobytes/ignis

## Demonstration brief

Record a continuous 30–45 second capture from the real engine:

1. Show the editor with a small scene and the MCP client's concrete instruction.
2. Inspect it, make one clear edit, then step and capture the same session.
3. Show the resulting scene and structured inspection; make the before/after
   obvious without speeding up a slow operation invisibly.
4. End with the repository URL, early-development label and commercial-license terms.

Label actual engine captures and illustrative website art separately. Avoid
private paths and conversations in recordings. Do not use the planetary
experiment to imply the planar terrain's appearance or completed spatial LOD.
The README already includes real stills with provenance; a new recording should
show an interaction that a viewer can reproduce from a clean checkout.

## Distribution sequence

| Stage | Useful action | Evidence to watch |
| --- | --- | --- |
| Public baseline | Source, readable README, working quickstart, license, Discussions and CI | Can a new visitor identify the use case and run the first command? |
| First demonstration | Publish a real short interaction and link the exact reproduction | First-run success/failure reports and useful questions |
| Relevant communities | Share once in suitable Rust, gamedev and MCP communities after reading their rules; adapt the technical angle | Qualified visitors, reproductions, useful contributors |
| Follow-through | Answer reports, fix onboarding issues and publish concrete improvements | Repeat contributors, issue resolution and working examples |

GitHub topics and a useful README support discovery. They do not guarantee
Trending placement or a star count. Rapid growth can depend on outside
distribution, timing and an existing audience; it cannot be honestly promised.
Describe the commercial profit royalty clearly; do not call this distribution OSI open source. Do not buy stars, automate endorsements, invent user counts or advertise
unmeasured performance.

## Measure without turning stars into the product

Use GitHub Traffic's available rolling views, unique visitors, clones and
referrers to evaluate each real announcement. Record dates and the window being
compared; a clone is not proof of successful use. Track first-run reports,
reproducible examples and contributor retention alongside stars. GitHub's
retention window is limited, so inspect it after a launch rather than claiming
historical attribution without data. No analytics service or recurring job is
required for this baseline.
